# Mission Trainer — правила для агентов

Браузерная 2D пошаговая стратегия для NASA Space Apps 2026 (челлендж «Build a Junior Astronaut Mission Trainer»).
Игрок 30 солов управляет лунной базой, балансируя энергию, жизнеобеспечение, еду и радиацию; главная сложность — пережить лунную ночь.

## Команды
- `npm run dev` — локальный сервер разработки
- `npm run build` — проверка типов и сборка в `dist/`
- `npm test` — тесты (Vitest)

## Карта папок и владельцы
| Папка | Что внутри | Владелец |
|---|---|---|
| `src/shared/types.ts` | Контракт между движком и интерфейсом | общий (только по договорённости) |
| `src/sim/` | Движок: `newGame`, `reduce`, `forecast` + тесты | движок/контент |
| `src/content/` | Данные: модули, события, факты | движок/контент |
| `src/ui/` | React-компоненты интерфейса | интерфейс |
| `src/mocks/` | Готовые `GameState` для вёрстки без движка | интерфейс |
| `src/App.tsx` | Точка сборки интерфейса | интерфейс |
| `public/sprites/` | Спрайты | интерфейс |
| `blender/` | Исходники 3D/рендеров спрайтов | интерфейс |

## Правила
- **НЕ менять `src/shared/types.ts`** без прямой просьбы человека. Это контракт между двумя людьми.
- `src/sim` — только чистые функции, без React и без DOM. Случайность — только через seed (свой ГПСЧ в состоянии/аргументах), **`Math.random` напрямую не использовать**.
- Интерфейс сам ничего не считает: состояние меняется только через `reduce(state, action)`, прогнозы — только через `forecast(state)`.
- Не добавлять новые зависимости без вопроса человеку.
- Работать только в своих папках (см. таблицу).
- Ветки: `ui/...` для интерфейса, `sim/...` для движка и контента. В `main` напрямую не пушить — только через pull request.
